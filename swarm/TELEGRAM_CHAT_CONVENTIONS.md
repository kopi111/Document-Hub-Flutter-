# Telegram-Parity Chat Swarm — Shared Conventions

You are ONE worker in a 15-agent swarm upgrading the JCF Document Hub chat to
Telegram-grade messaging, with LDAP-backed login. Read this file fully before
writing code. Every worker obeys these rules so the slices compose cleanly.

## Two repositories
- **Flutter app:** `~/projects/Document-Hub-Flutter-/` (most slices). Run
  `~/flutter/bin/flutter analyze <your files>` before you finish.
- **.NET API:** `~/projects/document-hub-api/` (auth + chat backend slices).
  Build with `dotnet build` from the repo root before you finish.

## The stable foundation — already built, DO NOT modify
These contracts are fixed. Read them; build against them; never edit them.

- `lib/models/chat/chat_message.dart` — `ChatMessage` now carries: `type`
  (`MessageType`), `attachment` (`ChatAttachment?`), `replyToId/Preview/Sender`,
  `reactions` (`List<MessageReaction>`), `editedAt`, `isDeleted`, `isPinned`,
  `isForwarded`, `forwardedFrom`, `ttlSeconds`, plus `preview` getter and a wide
  `copyWith`.
- `lib/models/chat/message_type.dart` — `MessageType { text, voice, image, file, location, system }` + wire mapping.
- `lib/models/chat/message_reaction.dart` — `MessageReaction { emoji, count, byMe }`.
- `lib/models/chat/chat_attachment.dart` — `ChatAttachment { url, name, sizeBytes, mimeType, durationMs, waveform, width, height }` + `readableSize`.
- `lib/screens/chat/chat_thread_controller.dart` — **the integration seam.**
  A `ChangeNotifier` owning the live message list. Call its typed methods; never
  mutate `conversation.messages` directly. Key methods:
  `sendText`, `sendAttachment(att, type:, text:)`, `forwardIn`, `receive`,
  `beginReply/beginEdit/clearCompose`, `applyEdit`, `deleteMessage`,
  `togglePin`, `toggleReaction`, `setDisappearing`, `markMyMessagesRead`,
  `markThreadRead`, `messageById`, `search`. Getters: `messages`, `isGroup`,
  `replyingTo`, `editing`, `pinnedMessage`, `disappearingTtlSeconds`.

## Hard rules
1. **Own only your files.** Each slice lists the files it creates/edits below.
   Touch nothing outside that list. In particular DO NOT edit
   `chat_thread_screen.dart`, `chat_message.dart`, or `chat_repository.dart`
   unless your slice explicitly owns it.
2. **No thread-screen edits.** Build self-contained widgets that accept a
   `ChatThreadController` (and a `ChatMessage` where relevant) and call its
   methods. At the TOP of your main widget file, add a `// INTEGRATION:` comment
   in 1–3 lines telling the integrator exactly where to drop your widget into
   `chat_thread_screen.dart` (e.g. "wrap each bubble with ReactionLongPress").
3. **Theme tokens:** reuse `lib/screens/chat/chat_style.dart` (`ChatStyle`) for
   colours/typography. Match the existing WhatsApp/Telegram look; no raw hex if a
   token exists.
4. **Reference fidelity:** `swarm/reference/` is a shallow clone of DrKLO/Telegram
   (native Android). Use it to get interaction behavior right (long-press radial
   reactions, swipe-to-reply, voice waveform, disappearing timers). You are
   re-implementing the behavior in Flutter, not porting Java.
5. **Clean Code:** intention-revealing names, functions that do one thing
   (2–20 lines), no comments that restate code, no `null` returns from public
   methods (use empty/Special-Case), throw on misuse. Leave files clean.
6. **No new heavyweight deps unless essential.** If you need a pub package
   (`record`, `image_picker`, `file_picker`, `just_audio`), add it to
   `pubspec.yaml` under your ownership ONLY IF your slice owns pubspec edits;
   otherwise implement a thin local abstraction with a stub that compiles, and
   note the package in your `// INTEGRATION:` comment. Prefer abstractions so the
   app always analyzes clean even without the native plugin.
7. **No `Generated by`/AI attribution anywhere.**
8. **Finish green:** your slice must pass `flutter analyze` (Flutter) or
   `dotnet build` (.NET) over the files you touched, with zero errors.

## Wire contract (Flutter <-> API)
snake_case JSON, `/v1` prefix, bearer token in `Authorization`. The message JSON
shape is whatever `ChatMessage.toJson()` emits (see foundation). API slices must
serialize to exactly those keys.

## Output discipline
Write real, complete, compiling code to disk. Do not print files to stdout and
stop. When done, end with a 5–10 line summary: files written, the public widget
names + their constructor signature, and your `// INTEGRATION:` note verbatim.
